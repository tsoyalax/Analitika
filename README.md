# Аналитика Reels-воронки

MVP дашборда сквозной аналитики Reels-воронки: считает конверсию каждого шага, сравнивает её с вашей обычной (медианой других ваших периодов), подсвечивает узкие места и разбирает воронку вместе с РНП через AI-ассистента на Claude.

**Воронка:** Охваты Reels → Написали в директ → Пришли в бота → Получили статью/подарок → Открыли статью → Дочитали → Перешли на сайт → Нажали кнопку тарифа → Открыли оплату → КЭП (диагностика, необязательный шаг) → Купили → Полная оплата.

На главном экране:

- **Плашка узких мест**: шаги, где конверсия хуже вашей обычной (медианы других периодов) больше чем на 25%. Пока период один, сравнивать не с чем — светофор выключен. Для каждого показано, сколько оплат и денег вы потеряли.
- **6 KPI-карточек**: Охваты Reels → Запуск бота / Директ → Статья и сайт → КЭП (диагностика) → Оплаты → Полная оплата. Нет данных — «—».
- **Воронка «Путь людей»** (ширина в логарифмическом масштабе): абсолютные значения, конверсия из прошлого шага и ваша обычная конверсия. Если этап больше предыдущего (туда приходят люди из соцсетей и по ссылкам), конверсия не считается.
- **График «Конверсия к вашей обычной»** (Recharts).
- **Деньги**: выручка, средний чек, выручка на человека в боте и на 1000 охватов. Тарифы и цены — кнопка «Тарифы»: дайте ссылку на сайт продаж, сервер откроет страницу, Claude выпишет продукт и цены (их можно поправить). Хранятся в `funnel_settings` (миграция `20261105200000_funnel_settings.sql` в kaizenhub); по умолчанию — тарифы [assets.therykunov.ru](https://assets.therykunov.ru).
- **Свои данные**: демо-цифр нет — период добавляется со скриншотов (до 6 снимков статистики бота, директа, Instagram, оплат: Claude переписывает с них цифры в форму, вы проверяете и сохраняете; только после входа в KaizenHub), вручную (форма «Ввести вручную», её же кнопка ✎ открывает для правки) или загрузкой CSV. Если вы вошли в KaizenHub, периоды сохраняются в Supabase; без входа живут до закрытия вкладки.
- **РНП**: текст рабочего недельного плана к выбранному периоду (вставить или загрузить .txt).
- **AI-ассистент**: кнопка «Проанализировать воронку и РНП» и чат. Ответ всегда идёт в формате 🔍 Диагностика → 💡 Гипотеза → 🛠️ 3 решения (быстрое, контентное, техническое).

## Запуск

Нужен Node.js 20.9+.

```bash
npm install
cp .env.example .env.local   # и впишите ключ
npm run dev
```

Откройте http://localhost:3000.

## Переменные окружения

| Переменная | Обязательна | Что делает |
|---|---|---|
| `ANTHROPIC_API_KEY` | нет | Ключ из [console.anthropic.com](https://console.anthropic.com/settings/keys). Без него ассистент работает в демо-режиме: анализ по правилам, без учёта текста РНП и без свободных вопросов. |

Ключ используется только на сервере (`src/app/api/analyze/route.ts`) и не попадает в браузер. Модель: `claude-opus-5-5`. Если модель откажется отвечать, запрос автоматически уйдёт на резервную модель (server-side fallback).

## Формат CSV

Одна строка на метрику: `метрика,значение`. Шаблон скачивается кнопкой «Шаблон CSV».

```csv
metric,value
reach,185000
dm,2246
bot,1654
gift,1288
opened,910
read,1026
site,1049
tariff,52
checkout,85
paid,14
solo,9
support,4
turnkey,1
automation_cr,0.4826
article_readers,2236
article_views,2981
total_payments,20
```

- Этапы можно указывать по id или по названию («Пришли в бота»).
- `solo` / `support` / `turnkey` — сколько продано каждого тарифа (по ним считается средний чек).
- Разделитель: `,`, `;` или табуляция. Пробелы в числах («1 654») допустимы.

## Как ищутся узкие места

Придуманных эталонов нет. «Обычная» конверсия шага — медиана этой конверсии по всем другим вашим периодам (`computeBaseline` в `src/lib/funnel.ts`). Шаг хуже обычного более чем на `BOTTLENECK_THRESHOLD = 0.25` (25%) — узкое место, на 10–25% — «ниже нормы». Пока период один и сравнивать не с чем, узкое место — шаг, на котором отваливается больше 80% людей (`DROP_BAD`), «ниже нормы» — больше 50% (`DROP_WARN`); переход «охваты → директ» не оценивается: охваты — просмотры, а не люди.

## Выкладка: сначала превью, потом main

```bash
npm run ship -- "описание изменений"
```

Скрипт коммитит изменения в ветку `preview` и открывает PR `preview → main`. Затем ждёт проверок GitHub Actions (линтер, типы, сборка) и только после вашего «y» сливает изменения в `main`.
